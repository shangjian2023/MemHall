# 长期发展路线

本路线用于安排后续维护；已交付成果以版本标签和验收记录为准，规划项不计为已实现能力。项目团队是维护主体，公开仓库是协作基础。

| 层次 | 目标 | 验收依据 |
|---|---|---|
| 稳定交付 | 持续维护麒麟安装、UKUI入口与通知、依赖兼容和版本回归 | 对应版本安装记录、离线流程与归档校验 |
| 能力扩展 | 完善不同智能体的记忆、行动与文件证据，增加独立场景 | 适配器契约测试、目标环境验证、公开用例与证据 |
| 评分质量 | 持续校准语义判卷，解释有效范围与不确定性 | 人工复核记录、金标准与回归结果 |
| 生态共建 | 共建办公、研发及多用户任务，复用题库与固定试卷 | 经过审阅的用例、PR与可重复执行的配置 |

## 近期维护

围绕当前发行版处理安装运行、证据完整性和用户反馈。维护依赖清单、版本说明和平台验收记录；在真实环境补齐不同框架的适配验证，不混用配置不同的实验结果。

## 中期演进

扩展独立任务场景，改进记忆与行动采集，完善评分校准与版本比较。新增接口先给出兼容性与验证方案，避免题量增长掩盖实际覆盖不足。

## 长期协作

openKylin用户可提供日常任务，框架开发者可贡献适配器和问题复现，集成团队可维护验收试卷。通过公开讨论、代码审阅和版本记录积累贡献与运营成果；有持续贡献和维护意愿的参与者可按治理规则加入维护。

参与入口：[贡献指南](../CONTRIBUTING.md)；职责与决策：[治理规则](../GOVERNANCE.md)。
