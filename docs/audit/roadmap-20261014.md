# 兼容性与探针路线图（2026-10-14）

依据五路调研：内部四路（适配器层 / 记忆调用探针 / 统一元规则 / 隔离沙箱，含本地未提交代码对账）
+ 外部两路文献（长期记忆基准 10+ 家；跨框架 harness 设计模式）。来源 URL 见调研底稿。
用途：对照赛题"六能力 + 自动多维指标 + openKylin 优先验证"查缺，TODO 分三档排优先级。

## 一、先说结论：我们对外部先例的三个坐标

1. **"同时横评多个异构完整 agent 框架"几乎无先例**。市面主流（LoCoMo/LongMemEval/
   MemoryAgentBench/MemBench）全是"记忆模块对比"：喂同一段历史给各家记忆 API 再出题。
   最接近的 OmniMemEval agent track 走"记忆插件协议"（点名 OpenClaw），也不是 subprocess
   包完整框架 CLI。README/dataset-card 可放心把这写成差异点。
2. **"agent 是黑盒，证据锚环境侧"是通行解法**（SWE-bench/tau-bench/OSWorld/GAIA 无一解析
   agent 内部记忆格式）。我们不必追求把各家记忆格式归一成同一粒度——判据锚定文件终态
   （FsDiff，本地版已到字节级 sha256）与行为（judge/规则），记忆导出定位为**诊断证据**，
   不做跨系统同条件比较的口径。这一条直接回答"痕迹异构怎么放同一把尺"。
3. **当前架构最准确的画像：两条腿不对称**。写侧/终态腿已经硬（canary 写侧陷阱 v2 全面
   使用 + FsDiff 内容指纹 + fs.artifact_matches 字节级验收）；**读侧（答题时到底检索没检索
   记忆）全项目零观测**，"答案对=用上了"是推断不是观测。补齐读侧的最优路径在网关（见 B1）。

## 二、做得好的（有外部对照背书，作品材料可直接引用）

- 证据层设计（pydantic 四类证据 + dump_ok/truncated/coverage 诚实标注 + sha256 封印 +
  verify 防篡改）——比 LoCoMo（数据公开跑烂、无防污染）严谨；HaluMem 的"操作级判卷"
  方向我们架构天然支持。
- 判卷防呆：decoy 负样本控制（喂故意错答案测 judge 假阳性，拒绝率门槛）——恰是 2026 年
  LoCoMo 社区审计（judge 放过 63% 故意错答）开出的药方；人工盲评工作表补 judge-人工对齐。
- "宁弃权不冤枉"：证据不足 → invalid_run 不进分母，不做硬降级——与"证据不足≠答错"的
  审计立场一致，优于宽松 judge。
- 统一模型网关（模型强制改写 + dummy key 记账归因）——控制变量"分清模型聪明还是记忆
  好"，外部少见的硬控制。
- 口径冻结 + compatibility.py 比较前强制核验（口径混杂拒绝聚合）+ R01 全套装印——
  应对"刷榜不真干活"批评（Berkeley 审计拆穿 8 个 agent 基准）的基础设施。
- 隔离三层扎实（reset+verify_reset 事故驱动修补史、凭据全 stdin、OS 文件锁互斥）。
