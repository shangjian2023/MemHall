# MemHall 参赛材料与修改指引

主交付：**[MemHall-作品介绍-可编辑版.docx](MemHall-作品介绍-可编辑版.docx)**。这是面向赛事评审的作品介绍，包含背景、架构、场景、数据设计、自动评分、系统验证、实测、创新、治理、测量边界及交付地图。

文档依据 2026-10-13 取得的官方命题与赛程，以及本地 v1.3.2 基线和逐轮实验留档制作。修复尚未发布，历史实验没有冒充为修复后的重新实测。

## 直接修改 Word

- 正文和表格为 Word 原生对象，可以修改；图表以图片插入，数据及可重建脚本另外提供。
- 封面 `MemHall Team` 按报名信息替换为实际团队/作者，补充联系方式与正式提交版本。
- 在来源/提交说明处补入团队确认的公开发行链接和至少两款真实智能体的 openKylin 演示视频链接。
- 删除或改写待办说明前，先完成其对应验收；不要把待重建包、mock 截图或单评委成绩写成已完成的新证据。
- 最后按 `Ctrl+A`、`F9` 更新域和目录，确认分页，再使用 Word 的“导出 PDF”/“另存为 PDF”。保留 .docx 便于后续修改。

**注意：构建脚本会覆盖主 Word 和 Markdown。直接手改 Word 后，应先另存副本；Word 的手改不会反向同步到 JSON。**

## 从公开资料重建 Word

在仓库根目录执行：

```bash
uv sync --frozen --group docs
uv run --frozen --group docs python scripts/build_submission_doc.py
```

脚本使用本目录的 CSV/JSON；不需要真实智能体凭据，也不修改原始实验。生成后在 Word 中更新目录。图表展示真实轮次与样本 SD，没有增加虚构实验或显著性标记。图表 SVG 可单独编辑。

仓库首页旧式多图由 `scripts/make_readme_figures.py` 重建，依赖本地完整历史 runs 与 aggregate 文件；它与这里的公开数据构建路径不同。外部使用者可直接重建本介绍文档，完整历史归档需由团队按脱敏规则另行分享。

## 离线样例与实测边界

```bash
uv run memhall verify docs/contest/submission/examples/20261013-085255-mock
```

样例为 6 题、14 探测（9 score、5 diagnostic），总体 55.6%；它证明解析、编排、证据、评分与报告连通。真实三家成绩见实验 CSV，实际判卷为规则 + 单 LLM A。18 轮中 14 轮通过当前完整性校验，4 轮缺失明确写在 Word 和审计报告中。

## 提交前最重要的事项

1. 找回缺失的真实原始证据或重跑相应归档，保留完整 trace 和版本；不能补造文件。
2. 重建修复版 .deb/exe，并在干净 openKylin 安装验收，避免源码与二进制错版。
3. 按 [演示讲稿](../../demo-script.md) 录制至少两款真实智能体的 3–5 分钟 openKylin 桌面演示；若团队已另存成片，核验后补链接。当前 v1.3.2 Release 未见视频附件。
4. 按参赛确认邮件核对实际提交方式，补齐团队、视频及公开发行信息；若补做独立评委校准，同步更新数据与口径。

官网核验的提交截止为 **2026-10-16 24:00**（赛事所在地时间），入围公布 10 月 21 日，总决赛 10 月 29 日。团队收到的专门通知需留档核对。
