## 0. 全局写作纪律（先读）

1. **评分权重就是章节配重**：数据设计 25%、自动评分 25%、任务定义与通用性 15%、稳定性与可复现 15%、指标完整性 10%、创新与工程落地 10%。第四、五章合计占一半篇幅精力，其余章节为它们服务。评审总纲原话："**重点关注方案能否在真实智能体运行证据上自动完成评测，并稳定区分不同模型或系统在长期记忆能力上的差异**"——每个字都是我们的现状，写报告时反复回看。
2. **匿名**：两份范本都因网评公平要求匿名。全文不出现学校/姓名/导师；贡献处写"团队"，代码引用仓库链接即可。
3. **数字单一来源**：所有分数/统计以 `scripts/stats_uncertainty.py` 输出和 README 终榜为准，禁止手改数字；显著性表述跟随统计口径（并列就是并列，不写成"显著优于"）。
4. **诚实优先**：mock 是缺陷注入基线（设计模式确定输出，不是难度地板）；未完成/降级项如实写并给原因（判卷未决→人工复核率）。评审里"可解释"比"分数高"值钱。
5. **图表复用现成资产**：images/radar-final-dual.png、report/panels.py 进阶图（verdict-mix/caliber/latency/memory/durations/probe-history/case-scores）、架构图重画（麒麟蓝 #3790FA / Okabe-Ito）。新图统一风格。
6. 页幅建议：正文 35–45 页 + 附录（范本区间 27–90 页，取中位偏上；内容密度优先于页数）。

## 1. 报告骨架（章→评委在看什么→放什么）

### 封面 / 目录 / 摘要（1 页）
- 摘要 400 字公式（貔貅式四段）：①战略背景一句（智能体进入 openKylin 生态，记忆能力成可用性关键，生态缺评测工具）→②三大痛点一句（人工检查难规模化 / 简单问答覆盖不了冲突更新·相似干扰·行动复用 / 自动评分语义偏移难区分"记住/误记/不该记"）→③方案一段（麟阁：三阶段剧本×六能力×七题型的可复现基准，四证据带哈希自动判卷，规则+LLM 双判+质检三件套，deb/CLI 工具化）→④成果数字（181 题 5 套题包、4 智能体真机横评、六维雷达与均值±CI、n 轮可复现）。
- 摘要里数字必须与第七章完全一致。

### 一、赛题与目标（0.5 页）
- 赛项一句话 + 我们的目标陈述（直接回应赛题"最终目标"段：自动产出多维指标、优先在 openKylin 上验证、服务社区持续评估）。短，别恋战。

### 二、背景与相关工作（3–4 页）——对应"任务定义与通用性"的一半
- 2.1 痛点展开：把赛题三个不足各写一段，每段结尾接"麟阁如何解"的一句预告（埋钩子）。
- 2.2 国内外现状（貔貅式分方向综述+对比表）：学术侧（长期记忆评测：LoCoMo 及其 2026 审计[判卷放过 63% 故意错答]、OmniMemEval agent track、记忆模块对比路线）+ 产品侧（各 agent 自带记忆系统无配套横评工具；openKylin 生态四家框架：KylinBot/kylin-agent/OpenClaw/Hermes）。收束到调研结论：**多异构完整框架的横向评测几乎无先例，主流全是记忆模块对比**——这是我们的空位，也回答"相较同类是否有明确优势"。
- 2.3 设计原则 3–5 条：agent 黑盒+证据锚在环境侧（不归一各家记忆格式）、自动化优先、可复现（冻结试卷/封印审计）、诚实统计。这些原则后面每章都在兑现。

### 三、总体设计（4–5 页）——"任务定义与通用性"主场之一
- 3.1 评测模型：**三阶段剧本（教→隔→考）**图 + 为什么（真实使用形态：不是一次问答，是跨会话留痕）；七题型表（任务链/跨会话召回/会话召回/假前提/相似/时间/信息更新）。
- 3.2 能力空间：六能力×六内容 36 格覆盖矩阵表（29/31/29/27/32/33 分布已有）——"指标完整性 10%"的直接证据。
- 3.3 判定模型：五态判定+故障定位四态+探测点 role 分流（score/diagnostic，诊断探针不进分母）——解释为什么分数可信。
- 3.4 总体架构图：runner/scoring/engine/judge/report/adapters/gateway/sandbox 分层 + 一条命令全链路产物（manifest/verdicts/metrics/radar/report/证据 JSONL）。**一张图讲清"证据→评分"闭环**，这是评审最想看的图。

### 四、题库与数据设计（6–8 页）——"数据设计 25%"主场，篇幅最大
- 4.1 数据结构：case.yaml 字段表（capability/content_type/question_type/difficulty/probes/verdict_map/anchors）+ 一道完整样例（建议 boundary 或 dynamic_update，展示"教什么→考什么→判什么"三段）。
- 4.2 五套题包表（full 45 / chains 4 / challenge-v2 72 / development-v2 39 / gen 21 = 181）+ 各自用途与身份（suite_id/指纹/冻结试卷 paper_id、四智能体同卷同序）。
- 4.3 区分度设计（评委最爱）：①双胞胎相似干扰（path-twin/owner-twin）；②动态更新的新旧信息对抗（wrong_reuse 类）；③边界陷阱（教了不该记的→考它是否拒记/拒答）；④canary 读侧探针（recall-v2-canary-read：教随机口令→问本体=考记忆、问未教槽位=考拒答，编造即 fabrication）；⑤temporal 拨钟（系统时间 +N 天考相对时间推理）。
- 4.4 可扩展与防背题：参数化生成器三旋钮（--distract/--gap-days/--similar，同 seed 逐字复现）；held-out 私有池+威胁模型（防训练污染不防定向重构，如实写）；出题四规矩（可判定/防污染/像人话/本土化）；lint 门禁（verdict_map 词表、覆盖矩阵校验、空格检查）。
- 4.5 覆盖矩阵统计表 + 难度分布（1/2/3 = 53/75/53）。
- 素材：dataset-card.md（几乎现成，改写语态）、cases/ 目录、lint_cases.py 输出。

### 五、自动评分方案（6–8 页）——"自动评分 25%"主场
- 5.1 四类证据带哈希：对话流/记忆快照/actions 轨迹/文件差异（fs SHA256 字节级），evidence_bundle 封印——回应"根据运行证据评分"。
- 5.2 三级判卷：规则判卷（锚例三层命中+拒答值门）→ LLM 评委（提示词带锚例、版本化 JUDGE_PROMPT_VERSION，v2.0.0 起单判一票定案）；判不了的转人工（human_review 不计分，不硬判）。
- 5.3 质检三件套（我们独有，重点写）：金标准自检（judge_selftest 错判 0 门禁，进 CI）；诱饵负样本（decoy 188/188 拒收）；人工盲评工作表（calibrate 导出 72 条双人分层抽样，v2.0.0 起取代双判成为第三件）。写清两层结构：评测流程内人工介入≈0（human_review 率是指标），判卷器质量靠流程外校准证据。LoCoMo 审计教训对照：不质检的 LLM 判卷会放过 63% 故意错答。
- 5.4 可解释输出：verdict_map 五类错误构成（correct/confusion/fabrication/omission/over_persist/wrong_reuse）、逐判定给出判定依据、mock 基线画像（62–66% 设计模式输出）证明判卷能逮住已知缺陷。
- 5.5 无效运行隔离：AgentUnavailable→invalid_run 出分母、降级不计分、故障定位四态——"区分正确记忆/遗漏/混淆/错误持久化/错误复用"逐条对上（赛题评分细则原文）。
- 素材：design.md §4/§6、契约 02/03、scoring 源码、decoy/selftest 输出样例。

### 六、工程实现与工具化（4–5 页）——"工程可落地"+"稳定性与可复现"
- 6.1 工具封装：CLI 一条命令全产物、Web UI（发车/直播流/人工复核）、.deb（UKUI 菜单项、冻结依赖、装机验收）+ Windows 便携 exe；三分钟上手（范本：三张截图）。
- 6.2 九适配器架构：统一接口+沙箱家目录隔离（零污染真实 ~/.hermes 等）；四家评测对象实接（含 kylin-agent 运行时源码级复核）。
- 6.3 统一模型网关：强制改写模型（构造 (agent,model) 二元组对照的仪器）、凭据单点+记账归因（每请求 token 记账、防"假忙"的账单对账三态 verified/suspect/unknown）。
- 6.4 实验可信度工程：OS 级 bwrap 沙箱（写面强制隔离）、拨钟恢复含单调耗时、run 互斥锁、UTC 口径、verify 封印审计（证据哈希复算）、失败轮归档不删除。
- 6.5 稳定性证据：CI 双平台矩阵（ubuntu+windows×py3.11/3.12）绿徽章；mock 三平台逐字一致（可复现性实证）；293→373 测试。
- 素材：README 三分钟上手节、environment 文档、verify 输出样例。

### 七、实验与结果（5–7 页）——"稳定区分不同系统"的最终证明
- 7.1 实验设置表：评测机（openKylin 3.0 VM/真机）、统一模型 qwen3.7-plus 经网关、sandbox=1、每家 n 轮、冻结试卷 seed、判卷口径（规则+单 LLM 评委——v2.0.0 定版，如实写）。
- 7.2 mock 缺陷注入基线：六维画像表 + "判卷逮住每个已知缺陷"的对应关系。
- 7.3 真机横评主结果：四家×六维雷达图（终版图）+ 均值±样本标准差表 + 题族聚类 bootstrap CI；**等 D 的 sandbox=1 四家新矩阵出数后回填**（当前先用 v3 三家 n=4 数字占位并标注"新矩阵进行中"，终版必须换）。
- 7.4 诚实统计：配对符号检验+聚类稳健检验的结论原样写（并列/不显著就写并列，功效声明"≈36 轮才能分开头部两家"）；轮间翻转率；判卷口径差（dual vs scripted -0.8~-19）；p50/p95 延迟与 token 记账覆盖。
- 7.5 行为画像举例（每家 1 个最典型发现：如 boundary 的 over_persist 稳定缺陷、hermes 概率性丢写 30%、kylinbot 结构化检索强/更新弱）——评审记故事比记分数牢。
