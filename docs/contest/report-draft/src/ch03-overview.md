# 第三章 总体设计

本章导读：一个记忆评测基准要先回答三个问题——怎么考（评测模型）、考什么（能力空间）、怎么判（判定模型），还需要一副把它们串起来的工程骨架（总体架构）。本章依次给出这四块设计；题库与判卷的细节分别在第四、五章展开。

## 3.1 评测模型：三阶段剧本与七类题型

把记忆评测做成"一次问答"是同类工作的常见简化：一段长历史喂进去，问一句、答一句、判一句。但真实使用不是这个形态——用户今天随口教一句"以后报表都用这个模板"，可能要到下周做报表时才第一次兑现。记忆能力的价值恰恰在跨会话留痕：隔了干扰还记不记得、信息改口了跟不跟新、不该记的是不是真没记。单轮问答量不出这些。

本作品把每个用例写成一段"教 → 隔 → 考"三阶段剧本，如图~phases~所示。教（inject）用用户口吻注入记忆目标，比如"我习惯把代码放在 ~/work/src""对了，改到 ~/dev/src 了，以后以这个为准"；隔（confound）插入无关话题干扰，然后结束会话，可选系统级事件——时钟前拨若干天模拟隔天、重启、断网；考（probe）做多时点探测：问答探测考语义，任务探测考行动——后者不听智能体嘴上说没说"完成"，判卷只看文件系统变化和行动轨迹。每个用例开始前适配器先清空或回滚记忆，用例之间互不污染。

隔一天为什么不真等一天？真实等待既昂贵又不可复现，剧本默认零等待：用结束会话加时钟偏移给出"隔天感"，确需真实等待时也可以按分钟配置——取舍的天平始终偏向"同一份剧本在任何机器上逐字重演出同样的时间线"。这套剧本还有两个要紧的细节。其一，探测点可以声明判定时点：教学一结束就判，还是考完再判——canary 类探测一律教学时点判，考段里"悄悄删掉"洗白不了"不该记的记下了"这个事实。其二，四类证据（对话、记忆快照、行动轨迹、文件差异）按阶段采集，判卷引用的每条证据都能对回时间线上的具体时点。三阶段的时序、会话切换点、拨钟注入点与证据采集时点，全部落在图~phases~的一张时间线上。

七类题型不是七个孤立的坑位，而是同一套三阶段剧本上的七种考法：跨会话召回考"记没记"，信息更新和时间理解考"跟不跟新"，相近区分考"分不分得清"，假前提考"会不会编"，任务链考"用不用得上"。full 集里跨会话召回 12 道，是最大的一族——"隔了会话还记得"正是长期记忆区别于长上下文的本质。需要如实说明一条测量边界：当前真智能体适配器每条消息都是独立进程（无会话内上下文），会话内召回在实测口径下等价于"写库后立刻检索"，长期保持实测的是"跨干扰保持"；这些收窄在题库数据集说明卡中逐条披露，不作修饰。

## 3.2 能力空间：六能力×六内容的 36 格覆盖

只报一个总分看不出结构：如果题库偏科——比如全考偏好记忆、路径类一次没测——总分再高也掩盖了短板。攒题凑数容易，覆盖是否均衡却没有对账物，评审无从检验。

本作品把"考什么"显式做成一张 36 格覆盖矩阵：纵轴是六项能力（长期保持、记忆调用、动态更新、相近区分、边界识别、任务复用，与赛题原文对齐），横轴是六类内容（偏好、路径、模板、事实、项目状态、临时敏感信息），如图~matrix36~所示。六类内容不是随手挑的：前五类覆盖桌面办公最常见的记忆对象，临时敏感信息单列，是给边界识别准备的主场。每道题进库前由 lint 门禁自动统计进矩阵：题必须可判定、敏感类题必须带 canary 假信息串，矩阵里哪个格是空的一眼可见。

36 格无空格不是巧合，是补出来的：团队最早合并的 14 道种子只覆盖 9/36 格，随后的 29 道补充题就是照着空格补的。重点格刻意加厚——full 集里 3 题的格有三处：记忆调用×事实、动态更新×路径、边界×敏感（后者含严格/宽松两档判定契约），其余格 1–2 题；另有 13 个 canary 用例（full 种子口径）和两道大容量注入题（一次教 16 条互不相关事实再考 5 条，专门制造检索竞争）。题库扩展到五套题包共 181 题后，六个能力的题量分布实测为 31/33/32/27/29/29，每个能力都落在 27–33 题的区间，没有任何一个能力空转。

## 3.3 判定模型：六态判定与探测点分流

自动评分最容易糊弄的有两处：一是把"答错了"和"没测到"混进同一个分母；二是只判对错，"记错的样子"分不开——而赛题评分细则要求的恰恰是区分"正确记忆/遗漏/混淆/错误持久化/错误复用"。本作品的判定模型围绕这两点设计，分三层。

第一层是判定值。每个探测点产出一条判定，值域六态：correct（记对了）、omission（忘了）、confusion（记混了，新旧或相似信息交叉使用）、fabrication（瞎编，无中生有题答出编造内容）、over_persist（不该记的记下了，canary 串出现在记忆里）、wrong_reuse（用错了，拿过期或张冠李戴的历史信息办事）。其中信息更新与时间理解题"答旧值"统一判 wrong_reuse——时间理解失败与旧值复用在"答旧值"这个行为上不可分，统一口径防归因污染。另有流程态：运行无效、判卷未决（转人工复核），单列统计，永不进分母。

第二层是分层判卷。能规则化的绝不用 LLM：文件是否存在、记忆里有没有这条目、回复是否精确匹配，由规则断言直接出结论；语义题升级给 LLM 评委——每道题自带评分标准、候选判定映射和至少两条锚例，评委只做分类、不做自由发挥，一票定案，无效票转人工复核。评委提示词版本随产物留痕，判卷配置纳入封存与对账条件。判不了的题如实进"待人工"队列，不硬判、不凑数。

第三层是探测点分流，这是分数可信的关键。探测点分 score 与 diagnostic 两层：只有 score 探测进六维分母；存储态断言（"存没存"）、行动轨迹断言、跨族 canary 抽查归入 diagnostic，只进故障定位与质检层。为什么这样切：一个"没写库"的故障，如果存储断言也计分，会在长期保持、动态更新、任务复用三处重复扣三次分——分数反映的就不再是能力差异，而是单点故障的传染。诊断信息流向故障定位四态：没存、存了没用上、存错了、该删没删，每条附证据引用，写进深化报告。

可信还有一道收尾：每条判定都同时给出判定依据（一句人话解释）与证据引用链，报告里任何一条分数都能下钻到原始证据——"可解释"不是事后补的说明栏，而是判定结构的一部分。分数可信的最后一道闸则是 fail-closed：记忆导出失败不等于空库，行动轨迹覆盖不全时"没找到动作"分不清是没做还是没记——这两种情况一律判运行无效、请出分母，而不是当错题计。换句话说，分数可信不依赖"裁判永远对"，而依赖"证据不足就不给分"。这套判定结构的逐态落位见表~t5-1-verdicts~，判卷器自身的量化质检证据（金标准错判 0 门禁、诱饵 188/188 拒收）在第五章 5.3 展开。

## 3.4 总体架构：从证据到评分的闭环

评测工具的常见状态是脚本散装、产物散落：换一家被测智能体要改一遍评测器，跑完没有审计手段，分数对不对全凭自觉。本作品的总体架构如图~arch~所示，六层自下而上：被测智能体（openKylin 真机四家加本机车道与 mock 基线，一律黑盒）；适配器层（统一接口：重置、发消息、结束会话、导出记忆、导出操作——新增智能体只需新增适配器，用例零改动）；执行层 runner（三阶段剧本编排、UTC 时间口径、运行互斥锁）；证据层（四类证据逐条 SHA256 封印）；判卷层（规则+单 LLM 评委，配金标准自检、诱饵负样本、人工盲评三件质检）；报告层（六维雷达、pass^k、verify 封印审计）。

{{fig:arch|麟阁总体架构|绘制中}}

这条架构的设计原则一句话：评分对象从"答案"前移为"证据"。跑完一个用例先落一份完整证据包，评分器只读证据包、不接触智能体——评分可以离线重跑、可以审计、可以复现，判卷口径升级后还能拿同一批证据重判。围绕这条主干还有两件外挂的可信度设施：统一模型网关强制各家被测智能体同一后端同一模型，OS 级沙箱约束被测环境的写面——两者属于实验环境的公平性工程，见第六章。

落到使用者手上是一条命令：

```bash
uv run memhall run -a hermes -c cases/full -o runs
```

一轮跑完，同目录得到 manifest（测量契约总账，记被测智能体版本、模型口径与 token 记账）、verdicts（逐判定带证据引用）、metrics（六维指标）、radar 雷达图、report 报告与证据 JSONL；`memhall verify` 对整轮产物做哈希复算，任何一条被改过的证据都会现形。目前适配器已接九个车道：openKylin 真机的 hermes、kylinbot、openclaw、kylin-agent，本机的 hermes-local、claude-local、qwen-local、opencode，外加 mock 缺陷注入基线——同一个题库、同一套判卷，换车道只换适配器。

以上是本章的总体设计。题库如何按这套模型生长——数据结构、五套题包、区分度设计与防背题——见第四章；判定与质检如何落地成三级判卷流水线、质检三件套如何量化，见第五章。
