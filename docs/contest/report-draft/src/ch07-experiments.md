# 第七章 实验与结果

本章回答"测出了什么"。我们先交代正式实验矩阵的设置与可信度保障（7.1），再用 mock 缺陷注入基线验证判卷器能不能逮住已知缺陷（7.2），然后给出四家真机横评主结果（7.3）与诚实统计口径（7.4），最后以每家一个最典型的行为画像收尾（7.5）。需要提前说明：截至本报告撰写，四家全量正式矩阵（sandbox=1）仍在评测机上运行，本章所有正式成绩一律以〔待填〕占位，出数后回填；凡引用历史数字均明确标注"历史批次"（归档 tool_version 1.3.1，统计口径为 v1.3.2 终榜 v3），不冒充新矩阵。

## 7.1 实验设置

横评要可信，前提是除了被测系统本身，其余变量全部锁死。智能体评测常见的失效方式是"看着比了、其实没比"：各家跑的题不一样、背后模型不一样、有的带隔离有的裸奔、判卷口径临时变更——这样得到的差值里混着模型、环境、试卷多种因素，说不清谁贡献了多少。

本作品把一次正式横评组织成一张完整登记的实验矩阵（如表~t7-1-setup~所示），四个环节全部仪器化。其一，被测对象为 openKylin 生态四家智能体（Hermes、KylinBot、OpenClaw、kylin-agent），均为完整框架黑盒，经各自适配器接入，记忆与配置互不共享。其二，三套正式题包（full 45 题、chains 4 题、challenge-v2 72 题）各自冻结一份试卷（seed 20261013），四家每轮同卷同序。其三，全部 case 在 sandbox=1 的 OS 级沙箱内执行，统一模型 qwen3.7-plus 经网关强制改写并逐请求记账。其四，判卷口径为规则+单 LLM 评委（v2.0.0 定版：一票定案，无效票转人工复核）。矩阵总规模为 4 家 × 3 题包 × 4 轮 = 48 场、1936 次 case 执行；另有 development-v2 39 题与 gen 21 题各 1 轮（8 场、240 次 case），只作开发与生成覆盖检查，不并入正式排名。

## 7.2 mock 缺陷注入基线

判卷器好不好，光看真机分数没法验证——你不知道它放过了什么。真机四家没有标准答案画像，无法直接检查"该抓的都抓了"。

因此本作品内置 mock 缺陷注入基线：mock 适配器按设计模式确定输出，在哪些探测点必须答对、必须遗漏、必须混淆、必须错误持久化，都是事先写死的。这样 mock 的六维画像就是判卷器的"已知考题清单"——判卷结果与注入缺陷一一对应，说明判卷器逮得住每一类已知缺陷；对不上就说明判卷器有洞，先修判卷、再谈真机。mock 同时承担工程职责：作为离线零 LLM 成本的全链路样例（样例 run 已通过 verify 封印审计），新环境装机先跑 mock 验证流程通、再上真机，不烧 token 也不冒充真实成绩。

## 7.4 诚实统计

分数只有配上不确定度才有资格参与比较。本章执行六条统计纪律：

1. 四轮差异不自动宣称显著：配对方向检验只作探索性描述；按题聚类复核（同题各轮方向票合并净方向后再检验）之后才谈排名，过不了检验就如实写"不显著"，不按均值硬排。
2. 并列如实写并列；功效不足就报功效声明（按观测方差，把两家分开需要多少轮），不硬造次序。
3. 分母干净：diagnostic 诊断探针、invalid_run、human_review、降级判定一律不进正式分母；无效率与人工复核率本身作为指标如实统计。
4. pass^k 报完整分母与保守下界，不用乐观口径充数。
5. token 逐请求记账并报告记账覆盖率；价格未配置时费用记 unknown，不做换算。
6. 延迟报 p50/p95，不报单轮最快值。

统计工具按上述纪律实现：输入实验索引后先过兼容性检查（题包版本、试卷 ID、评分协议、判卷器配置、产物封印逐项核对），再按 suite/sandbox/model/judge 分组输出六类结果——同探测点跨轮一致率、配对符号检验、每维组间/组内方差比、判卷口径差（同证据双口径分差，作为仪器方差上界之一）、功效声明、正式统计（均值±样本标准差、bootstrap 置信区间、六维、pass^k 条件通过率/覆盖率/保守下界、有效率）。置信区间把同题族的探测点一起重采样、并按整轮重采样，避免把同题多个高度相关探测点当成独立样本；sandbox=1 主矩阵与 sandbox=0 对照臂分开建索引，不混合聚合。

作为统计方法演示，引用历史批次（归档 tool_version 1.3.1、统计口径为 v1.3.2 终榜 v3，full 45 题 × 4 轮，规则+单 LLM 评委）的现成结论：三家总体分别为 hermes 74.6%±2.8、openclaw 72.5%±4.9、kylinbot 58.5%±6.8；探索性配对票检验中 hermes vs openclaw p≈0.752、hermes vs kylinbot p<0.001，而按题聚类复核后三对均回到不显著（p=0.163 / 0.121 / 0.572）——方向一致但 n=4 撑不起显著性结论；头部差距约 2.1 个百分点，按观测方差的近似功效估计需约 58 轮才能分开。同口径 chains（4 题 × 2 轮）下 hermes 与 openclaw 均 40.0%±0.0，并列如实写并列。这组历史数字演示的正是纪律本身：n=4 撑不起的结论就不下。

历史批次还有一条进档案的教训：初版终榜（openclaw 67.1 > kylinbot 52.4 > hermes 44.4）测于评测器三处缺陷修复之前——判卷客户端遇一次非 200 即全场失效、fresh 沙箱缺 DB 被误判导出失败、NAT 大包 TLS 损坏——仪器噪声混进了分数；修复后同配置重跑，hermes 稳定在 73% 上下。所以本作品把"系统故障不算智能体记忆能力弱"立为规则：废轮全量留痕，仪器修复前后的分数不可比，历史归档不删不改。

判卷器自身的校准证据也如实交代：人工双人盲评工作表 72 条已从 14 轮通过核验的历史归档导出，当前状态为 awaiting_human_labels——人工标签到齐前不存在"判卷一致率"数字，本章不引用；独立评委 B 因网关仅授权 qwen3.7-plus 未配置，评委与被测同模型标识的偏袒风险如实披露，校准出口即上述流程外盲评。如图~ci-final~、图~verdict-mix~与图~passk~所示，正式矩阵出数后本节将回填：置信区间与聚类稳健检验结论、六态判定构成（错误集中在哪一维）、pass^k 分母与保守下界；延迟 p50/p95 与 token 记账覆盖为〔待填：新矩阵延迟与记账覆盖统计〕。

## 7.5 行为画像举例

分数是简历，行为画像是性格——评审记故事比记分数牢。以下取历史批次（v1.3.2 口径，n=4）中每家最典型的一个发现；四家新矩阵出数后按同框架更新（〔待填：新矩阵行为画像〕）。

hermes：六维最均衡的选手，边界识别 83% 三家最高——"该忘的忘得掉"，这是长期记忆系统最难得的自觉。代价是轮间波动明显，部分维度 ±11 的轮间摆动提醒我们：分数均衡不等于每轮都稳。

openclaw：记忆调用与任务复用双高（77% / 89%），却是边界识别塌方（40%）——该忘的忘不掉，over_persist 在两轮中各占 12 / 87，构成教科书级的稳定缺陷签名。"什么都记"不等于"记得好"，单一总分掩盖的正是这类性格。

kylinbot：动态更新（17%）与相近区分（47%）拖垮总分——"改不动、分不清"；但边界识别 75%±5 反而三家最稳，"记该记的"做到了。总分垫底的系统也有单项第一，这正是六维指标优于单一榜一名次的地方。

kylin-agent：适配器已接入并配置独立网关身份，但截至本报告撰写，VM 真机验收尚未完成——如实写"无实测成绩"，不引用任何其他家分数推断其能力，其画像待正式矩阵出数后补齐。

chains 任务链口径下还有一条三家共同的短板："记了但用不上"——长期保持维分数不低的系统，到了"凭记忆真实生成产物"这一步照样掉链子。这类跨维落差只有多能力×多证据的测量能暴露，也是本基准区分于"问答对答分"的核心价值。
