# 第一章 赛题与目标

本章先交代赛题要求与评审关切，再给出本作品的目标陈述；后续各章的方案、数据与实验都围绕这一目标展开。

本作品参加 openKylin 开源 AI 工具赛道，赛题为"面向 openKylin 操作系统的智能体长期记忆自动化评测 Benchmark 设计"。赛题的判断是：随着大模型智能体进入办公、研发和个人助理等场景，能否长期、稳定、可控地记住用户信息，已经成为影响智能体可用性的关键能力；openKylin 生态中已支持 KylinBot、kylin-agent、OpenClaw、Hermes Agent 等智能体框架，但缺乏一套与之配套的系统级自动化评测工具。赛题要求把对话、记忆记录、行动轨迹、文件等运行产物统一组织为证据，并据此自动评估六个方面的能力：长期保持、记忆调用、动态更新、相近区分、边界识别、任务复用。评审总纲把检验标准概括为一句话："重点关注方案能否在真实智能体运行证据上自动完成评测，并稳定区分不同模型或系统在长期记忆能力上的差异"——这句话是全篇的靶心，本作品的第四、五、七章分别在回答"证据从哪来""评分怎么自动""区分得稳不稳"。

麟阁 MemHall 的目标直接对应赛题"最终目标"段的三句话，且各有一条可检验的兑现路径。一是自动产出多维指标：不止单一总分，六维能力独立出分，附错误构成与运行无效率等过程指标（见第三、五章）。二是优先在 openKylin 系统上完成验证：被测对象就是生态智能体，评测主机为 openKylin 3.0，配套真机系统级测试与 .deb 目标机构建（见第六章）。三是服务 openKylin 社区的持续评估：工具、题库与实验协议全部开源，冻结试卷可被社区复用，持续追踪智能体的版本演进（见第九章）。

# 第二章 背景与相关工作

本章回答两个问题：长期记忆评测为什么难（2.1），现有工作做到了哪、空位在哪（2.2）；最后给出贯穿全文的四条设计原则（2.3）。

## 2.1 三个不足与麟阁的切入点

赛题点名的第一个不足是评测依赖人工检查，难以规模化。要判断一个智能体记没记住、忘没忘掉，人工做法是反复对话、翻记录、凭印象打分：一个被测对象一轮就要耗费数小时，评分者之间难以一致，换个人重跑结论可能就变。更麻烦的是证据形态——对话记录、记忆文件、操作痕迹散落在各自目录里，人工对照既慢又容易漏。麟阁的解法是把评测做成"教→隔→考"剧本驱动的一键流水线：证据自动采集封印，判卷自动执行，人工介入被压缩到流程内可观测、可计数的位置（见第三、五章）。

第二个不足是简单问答式验证覆盖不了真实使用形态。一问一答只能测"当场记住了吗"，测不了三类高频场景：冲突更新（用户改了地址，旧条目删没删）、相似干扰（两条只差一字的信息，取的时候拿哪条）、行动复用（记住的信息有没有真的用进任务）。这些恰是日常使用中最容易暴露缺陷的地方。麟阁的解法是三阶段剧本（教学注入→干扰隔离→多时点探测）配合按六能力组织的题型矩阵，把冲突更新、相似干扰、任务复用做成专门的题型族，而不是靠通用问答捎带覆盖（见第三、四章）。

第三个不足是自动评分的语义偏移：难以稳定判断模型到底是"记住了""误记了"还是"不该记却记了"。判卷若只输出对错，"没教过却编了一个"与"忘了"混为一谈，分数失去诊断价值；引入 LLM 判卷又带来新风险——2026 年社区对 LoCoMo 的审计发现，不设质检的 LLM 评委放过了 63% 的故意错答。麟阁的解法是六态判定加分层判卷（规则先判、单 LLM 评委兜底、无效票转人工复核），并给判卷器本身配三件质检：金标准自检门禁、诱饵负样本、人工盲评（见第五章）。

## 2.2 国内外现状

### 2.2.1 学术侧：三条评测路线

**超长对话记忆线。** LoCoMo 提供 10 段超长多会话对话、1,986 条问答（含多跳、时序与对抗性"未提及信息"题），平均 300 轮、最多 35 个会话；LongMemEval（ICLR 2025）规模 500 题，定义信息抽取、多会话推理、时序推理、知识更新、拒答五项核心能力、七种题型，并为每题标注证据会话。这条线证明了"长对话＋证据标注"的可行性，但被测对象是聊天模型或记忆接口，不是在桌面操作系统里运行的完整智能体。

**记忆操作与更新线。** MemoryAgentBench 把静态数据集改造为增量多轮流式输入，其反事实更新对（FactConsolidation）专门测新旧事实覆盖——主流记忆框架在这一项上大幅落后于"永远取最新"的朴素基线（Mem0 18%、Zep 7%，最强的 RAG 基线也仅 54%）。这预示"动态更新"维度天然区分度极高，也是麟阁题型设计的直接依据之一。

**记忆安全与审计线。** MPBench 系统化测记忆投毒，采用"写入阶段检查＋延迟复用检查"两阶段法，并发现写入通道越多、投毒面越大（其测得 Hermes 平均攻击成功率 66.67%、OpenClaw 34.25%）；MEMPROBE 则不看出门答案，直接审计"记忆产物里能恢复出什么用户状态"。这些方法支持了边界识别维度的设计——但良性的"临时信息不该记、敏感信息不该记"此前无人系统覆盖，现有工作都是从对抗攻击视角切入。

判卷侧的共识与教训值得单列：LLM 判卷已是主流做法，但 LoCoMo 社区审计显示不设质检的评委可以放过 63% 的故意错答——判卷器自身需要质检机制，这一点在既有基准中基本无人处理。

### 2.2.2 产品侧：生态智能体各有记忆，无配套横评

openKylin 生态的 KylinBot、kylin-agent、OpenClaw、Hermes Agent 记忆机制差异极大：OpenClaw 以纯 Markdown 文件为载体（精选长期记忆＋每日日志＋混合检索）；Hermes 把记忆全量注入系统提示词，没有独立检索层；KylinBot 的记忆存在应用内存储中，前端可可视化编辑；kylin-agent 的后端运行时与 Hermes 同构。赛题原文明确指出：生态"缺乏一套与之配套的、系统级的自动化评测工具，导致不同智能体在 openKylin 操作系统上的记忆能力难以量化比较"。各框架文档里能看到各自的记忆特性介绍，但面向完整智能体的同尺横评工具，生态里是空白。

### 2.2.3 收束：完整框架横评的空位

团队在立项前后对十余家外部基准与跨框架 harness 设计做了内部四路代码面加外部两路文献的调研，结论可以收成三条。其一，主流长期记忆基准（LoCoMo、LongMemEval、MemoryAgentBench、MemBench）全是"记忆模块对比"：把同一段历史喂给各家记忆接口再出题；最接近完整智能体的 OmniMemEval agent 轨道也走"记忆插件协议"，而不是把完整框架的命令行进程当黑盒驱动。其二，"agent 是黑盒、证据锚在环境侧"是成熟领域的通行解法：SWE-bench、tau-bench、OSWorld、GAIA 无一解析 agent 内部记忆格式。其三，两条合起来看，"同时横评多个异构完整智能体框架"的系统性评测几乎无先例；且现有基准普遍没有操作系统级证据、没有证据封印与哈希链，复现停留在"脚本可跑"而非"结果可审计"。此外，此前没有工作在真实桌面操作系统上评真实智能体，OS 级证据（文件产物、行动轨迹、系统状态）无人采集。

麟阁的位置正落在这个空位上：以子进程驱动完整智能体命令行，九个适配器覆盖 openKylin 真机四家、本机车道与 mock 基线，判据锚定环境侧运行证据。如图~landscape~所示，麟阁与既有方案在四个维度上的差异一目了然；表~t2-1-related~给出逐项对照。

## 2.3 设计原则

**原则一：被测智能体是黑盒，证据锚在环境侧。** 四家智能体的记忆载体从纯 Markdown 文件到应用内存储各不相同，强行归一会把评测器绑死在某一家实现上。麟阁不解析任何一家的记忆内部格式，判据只锚定两类环境侧证据：文件终态（字节级内容哈希）与可观察行为；各家的记忆导出仅作诊断参考，不进判定口径。这条原则在第三章的证据层定义与第六章的适配器、沙箱设计中兑现。

**原则二：自动化优先，人工介入可量化。** 赛题要求"尽可能自动化、低人工介入"。麟阁不承诺零人工，而是把人工的位置设计得可观测：判卷流程内，规则与 LLM 评委都判不了的判定单列转人工复核、不计入分母，人工复核率本身是报告指标；判卷器的质量靠流程外校准证据背书——金标准自检错判为零的门禁、188/188 全数拒收的诱饵负样本、72 条双人分层抽样的人工盲评。兑现见第五章。

**原则三：可复现是工程属性，不是口号。** 同一输入必须得到可对账的结果：冻结试卷保证四家同卷同序，统一模型网关强制同一后端同一模型，UTC 口径与拨钟恢复管住时间因素，证据封印（哈希逐条复算、残缺轮无法混入）管住产物可信，n 轮聚合给出均值与不确定度。兑现见第四、六、七章。

**原则四：诚实统计，口径先行。** 并列就写并列，不显著就不写显著；换判卷口径分数会怎么动，如实报告；威胁模型（防训练污染、不防定向重构）写进文档。这条原则决定第七章的写法——结论跟随统计口径，不做超出样本量的推断，也贯穿全篇的数字出处纪律。

这四条原则是一条因果链：因为证据锚在环境侧，异构完整框架才能同尺横评；因为流程自动化且判卷自带质检，人工才能降到可量化；因为试卷冻结与证据封印，结果才可复现；因为口径诚实，区分度结论才可信。后续各章逐一兑现。
