# 第八章 创新与特色

本章把全篇收拢成八条：每条一句话创新主张，配一句可对账的证据，证据里的每个数字都能在第三至七章或仓库文件里找到出处。这八条同时也是答辩 PPT 的骨架。

**其一，把完整智能体框架当黑盒横评，证据锚在环境侧。** 主流长期记忆基准全是"记忆模块对比"，最接近完整智能体的轨道也走记忆插件协议；麟阁以子进程驱动完整框架的命令行进程，不解析任何一家的记忆内部格式，判据只锚定文件终态与可观察行为——九个适配器统一接口，接通 openKylin 真机四家（hermes、kylinbot、openclaw 已 VM 实测联调，kylin-agent 已接入、待真机验收）、本机车道与 mock 基线（见表~t6-1-adapters~），新增智能体等于新增一个适配器，题库与判卷零改动。

**其二，"教→隔→考"三阶段剧本×七类题型×36 格能力空间。** 教学注入、干扰隔离、多时点探测（含拨钟跨天）还原真实使用形态，七类题型从七个角度拷问同一段记忆（见表~t3-1-qtypes~）；六能力×六内容覆盖矩阵全库 181 题无空格，每个能力落在 27–33 题区间（见表~t4-3-stats~），指标完整性有对账物；区分度也藏在题里——双胞胎相似干扰、新旧信息对抗、边界陷阱、canary 读侧探针与拨钟五类针对性设计，把"没记住、记混了、不该记的记了、用过期信息、凭空编造"分开计费（见第四章 4.3）。

**其三，六态判定加故障定位四态的可解释评分。** 不止判对错，还判"记错的样子"——correct、omission、confusion、fabrication、over_persist、wrong_reuse 六态逐条落位赛题"区分正确记忆、遗漏、混淆、错误持久化、错误复用"的评分要求（见表~t5-1-verdicts~）；每条判定附判定依据与证据引用，行为×存储交叉定位再把错误拆一层（没存、存了没用上、存错了、该删没删）。

**其四，判卷质检三件套，给判卷器本身打分。** LoCoMo 社区审计显示，不设质检的 LLM 评委会放过 63% 的故意错答；麟阁给判卷器配三件流程外质检：金标准自检错判 0（门禁进 CI）、188 条诱饵负样本 188/188 全拒收、72 条双人分层抽样盲评工作表——三件各管一头：第一件测"该对的判对"，第二件测"该错的判错"，第三件和人类对表（见第五章 5.3），判卷可信性由证据背书，而不是由口号背书。

**其五，统一模型网关是对照仪器，不只是代理。** 模型强制改写让"四家同模型"从配置自觉升级为可验证的事实，(agent, model) 二元组把归因做到每个请求；逐请求 JSONL 记账、限速退避，账单对账给出 verified/suspect/unknown 三态结论——"必经网关"配上了"该来没来"的检查（见第六章 6.3）。

**其六，OS 级实验可信度工程。** bwrap 整根只读加白名单可写的 OS 沙箱、拨钟恢复含单调耗时、宿主-评测机钟差超 ±300 秒拒跑的闸门、run 互斥锁、UTC 口径，合计 18 项隔离守卫测试托底（见第六章 6.4）——把"假设被测环境配合"升级为"不依赖配合"。

**其七，冻结试卷加封印审计的可复现体系。** 试卷 ID 是完整内容的 SHA-256，四家同卷同序，封存后禁止历史轮换；四类证据逐条 SHA256 封印，`memhall verify` 离线复算，残缺轮进不了任何统计——盲评抽样框自动排除 4 轮证据残缺归档，就是这道闸的实际运作；pass^k 报完整分母与保守下界（见第四章 4.2、第五章 5.1）。

**其八，deb/exe/CI 双平台的开源工程化。** .deb 在 openKylin 目标机原生构建（离线 wheels、UKUI 菜单项、卸载一条命令），Windows 便携 exe 双击即进 Web UI，CI 双平台四配置矩阵每次提交跑金标准门禁与 378 项全回归（见第六章 6.1、6.5）——社区用户装一个包、跑三条命令即可复现评测。

需要如实说明：这八条不宣称单项方法的学术首创——六维名称、LLM 判卷、合成模板都各有先例；麟阁的创新叙事落在组合与证据链上：上述能力在同一套工具里互相咬合，每个分数都能对回可审计的证据。

# 第九章 应用前景与社区价值

本章回答"比赛之后它还剩什么"：对 openKylin 社区是一套可复用的持续评估设施，对开源社区是一份治理齐备的工程资产，对更外部的场景是三种直接的迁移用法。

## 9.1 openKylin 社区的持续评估设施

智能体框架会持续演进，评测工具最怕的是"评完即弃"。麟阁的冻结试卷为此设计：试卷保存完整用例、ID 是内容的 SHA-256、封存后禁止历史轮换，社区可以拿同一份冻结试卷去追踪任一智能体的版本演进——新版本跑同卷，六维雷达直接对比，分数还能对账到当时的判卷口径与模型口径（manifest 记账）。评测产出的报告卡本身就是标准件：六维雷达、六态判定构成、运行无效率、延迟 p95 加 verify 封印校验，构成一份"记忆体检报告"，谁跑的、跑的哪版、判卷口径是什么，报告自己说得清。对生态维护者，这意味着"发新版不再靠体感"：一次改动有没有伤到记忆能力，同卷一跑便知，历次结果还能在版本之间纵向排列。

## 9.2 开源治理与长期发展

治理面按开源惯例齐备：Apache-2.0 许可，GitHub 与 Gitee 双托管（仓库地址见 README 与交付材料），CONTRIBUTING 收写出题四规矩与适配器契约，行为准则、安全策略、issue 与 PR 模板在库；评测口径变更必须在 CHANGELOG 记口径而非只记数字，CI 每次提交重跑金标准门禁，回归不回退。后续方向已在路线图中排定三项：一是读侧网关探针——解析过网流量的请求体重构"记忆读写调用轨迹"，把目前全项目零观测的"答题时到底检索没检索记忆"变成观测；二是 auditd 行动证据接线，补足行动轨迹的覆盖面；三是 sandbox=0 对照臂与 oracle 对照臂，把记忆净贡献和"检索不到/读不出"分开归因。这三项都在现有架构上生长，不需要推翻任何一层。对贡献者，契约先行降低了参与门槛：适配器只做转发消息、导出记忆、导出操作、管理会话生命周期四件事，出题守四规矩，贡献什么、怎么验收都写在文档里（见第四章 4.4.3、第六章 6.2）。

## 9.3 场景外推

三处直接迁移。个人助理选型：用户在自己的机器上对几个候选助理跑同一份试卷，六维雷达就是选型依据，mock 车道保证流程先通、再上真机。企业内网验收：智能体采购或上线前，以冻结试卷做验收门禁，凭证据封印与网关账单对账逐项检查交付方有没有"刷分"，验收结论可复算。记忆系统回归测试：记忆模块的开发者每次改动后跑一遍题包，六维分数与六态构成就是回归报告——判卷器逮得住已知缺陷（第七章 mock 基线），回归才谈得上可信。三种场景用的是同一套题库与判卷，不需要为场景另起炉灶。

# 第十章 总结

本作品做了三件事。做了什么：一套面向 openKylin 生态的可复现自动化记忆评测基准加工具——181 题五套题包、三阶段剧本、四证据带哈希自动判卷、一条命令全产物。证了什么：在真实运行证据上，六维指标能稳定区分不同智能体的记忆行为差异——历史批次三家形态各异（均衡、塌方、偏科），mock 缺陷注入基线证明判卷逮得住每类已知缺陷，诚实统计给出不确定度与功效边界。留给社区什么：开源的工具、题库与实验协议——Apache-2.0、双托管、冻结试卷可复用、路线图排定了读侧探针与对照臂，评测设施在比赛之后继续为生态工作。我们希望记忆评测从"每家自说自话"变成"同一把尺上的读数"——麟阁就是那把尺，外加造尺、验尺、用尺的整套工艺。

## 附录 B 复现指南

装依赖、体检、离线跑通全链路，三条命令（mock 适配器不配任何 API key 即可运行）：

```bash
uv sync --group dev
uv run memhall doctor
uv run memhall run -a mock -c cases/full -o runs
```

跑完用 `uv run memhall verify runs/<run_id>` 复核产物封印；真机车道把 `-a mock` 换成 `-a hermes` 等适配器名即可，前提是目标智能体已安装并配好你自己的模型凭据（麟阁不内置任何凭据）。
