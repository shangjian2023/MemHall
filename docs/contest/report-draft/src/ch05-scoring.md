# 第五章 自动评分方案

评测的公信力，最后都落在"这个分是怎么打出来的"上。本章讲麟阁的自动评分体系：判卷只认带哈希封印的运行证据（5.1）；规则、LLM 评委、人工复核三级流水线各司其职，判不了的不硬判（5.2）；判卷器本身被三件质检工具盯着体检（5.3）；每个判定都能下钻到证据与判定依据（5.4）；基础设施故障与真实能力缺陷严格分账（5.5）。

## 5.1 四类证据与封印：判卷只认落盘的运行证据

不少评测的判卷器只看智能体的最后一句回答，回答"看起来对"就给分。这有两个毛病：一是分不清"没记住"和"记了没用上"，错误原因全糊在一起；二是证据不留存证，事后没人能审计"这个分对应的那次运行到底发生了什么"，改个日志就能洗分。

麟阁把一次运行的所有痕迹统一为四类证据，按统一信封逐条落盘：①对话流——教、隔、考每一阶段的对话逐条记录，含耗时与 token；②记忆快照——教学段与考试段结束后各导出一次记忆库，导出成败带诚实标记，"导出失败"不会被折叠成"空库"洗白；③行动轨迹——考试段后采集的工具调用记录，附完整度标注：记录不完整时"没找到动作"分不清是没做还是没记，对应断言一律不判分；④文件差异——文件系统阶段前后对比，新建、删除的文件以 SHA256 字节级哈希计入。信封里连系统时钟偏移都有记录（拨钟题判相对时间的依据），每条证据载荷另有哈希指纹，防篡改、可比对。

如图~evidence~所示，一次 run 的产物——manifest 总账单、逐题证据、判定结果、指标报告——落成固定目录并逐层封印：题单快照、逐题证据、证据包整体、输出产物各有 SHA256。`memhall verify` 对归档离线对账：逐条复算证据哈希、校验格式与判定引用有效性——残缺轮直接判不通过。这道闸是真实用过的：5.3 的盲评抽样框只收 verify 通过的历史归档，18 轮里 4 轮因证据残缺被自动排除，进不了任何统计。

## 5.2 三级判卷流水线：规则打底、评委分类、人工兜底

自动判卷两头都会翻车。纯字符串匹配既分不清语义等价（换个说法就判错），也挡不住近形干扰（`~/proj/api` 与 `~/proj/api-v2` 只差一个后缀）；反过来把判卷整个交给裸 LLM，判定标准随措辞漂移，还无人担保它不"心软"。麟阁用三级流水线让每一级只做自己有把握的事，如图~pipeline~所示。

**第一级：规则判卷（确定性、可复现）。** 规则断言只读证据：文件终态、存储态等按题判定；所需证据不在场就判"证据缺失——运行无效"，绝不退化到判卷机本地凑数。语义探测点走脚本判卷：期望答案匹配之外用锚例三层命中——①尾段命中，回答尾段的取值与区分词整体出现才算，半对回答不放过；②关键值全中；③重叠率不低于 0.8 兜底，锚例带区分值而回答里没有时不得按锚例判（防"同模板异值"串台）。拒答另有值门：回答含"不知道"时，还要看期望值与锚例值的特征字符是否全缺——改述正确、顺带一句"旧记录没找到"的混合话术不会被误判成遗漏。发现超串近形干扰（前缀互含的异值）时脚本不定案、转下一层。规则判不了就显式弃权，不瞎猜。

锚例是什么：每道语义题在出题时自带"锚例"——什么样的回答该判什么，随题存档（见第四章）。它既是脚本判卷的匹配模板，也是下一级评委的参照例。

**第二级：单 LLM 评委（语义分类）。** 提示词随题下发判卷标准 rubric、判定词表 verdict_map 和锚例，要求输出严格 JSON：判定、置信度、证据引用、理由——无证据引用不得分，禁止臆测。v2.0.0 起一票定案：输出有效即采信，无效（类别不在词表内等）转人工复核。提示词版本号（JUDGE_PROMPT_VERSION，当前 2026-10-04）随 manifest 落账，任何一轮的分数都能对账到当时的判卷口径。评委端点整体不可用时降级脚本判卷兜底：判定值保留供复核但不计分（指标单列、保守下界按错计），机器故障不会静默混进分数。

**第三级：人工复核出口（human_review）。** 前两级都判不了的进待复核队列：不计分、不硬判、单列统计。人工复核率本身是输出指标（设计目标低于 5%）——它衡量的是题目可判定性和判卷器覆盖面，而不是被测智能体的表现。

> 设计取舍：为什么单评委而不是双评委仲裁？历史方案里评委 B 与评委 A 同模型标识，两票高度相关，仲裁给不出独立第二意见；跨厂商评委又受模型授权所限。v2.0.0 把这份预算挪给 5.3 的质检三件套——给判卷器做体检，比配一个"影子判官"更能回答"凭什么信它"。

## 5.3 质检三件套：给判卷器本身打分

自动评分最容易被追问的一句话是：凭什么信你的 LLM 评委？麟阁的回答分两层。第一层，评测流程内人工介入约等于零：从证据到分数的链路全自动，人工只出现在未决复核出口，且复核率本身是被报告的指标。第二层，判卷器的质量由三件流程外的质检证据背书——金标准自检、诱饵负样本、人工盲评，它们都不接触正式分数的产出流程，是专门"给判卷器打的分"，如图~qc-trio~所示。

{{fig:qc-trio|质检三件套量化结果|待出数}}

这套设计有明确的反面教材。2026 年社区对知名长期记忆基准 LoCoMo 的审计发现，其自动判卷放过了 63% 的故意错答——判卷器"心软"时分数会系统性虚高，而只拿答对的题测一致性根本发现不了宽松偏差，必须专门喂错答案、测假阳性。三件套正照此配置：第一件测"该对的判对"，第二件测"该错的判错"，第三件和人类对表。

### 5.3.1 金标准自检：错判 0 的门禁

金标准案例取自 2026-09-28 对 23 个探测点的三方人工对照审计（保留智能体真实回答原文），外加构造的边缘样本：新旧信息并列、真话豁免不等于编造、泄露口令等容易误判的形态。它有两种用法：离线模式下，同一批金标准喂给脚本判卷器，错判必须为 0——这道门禁进了 CI，任何改动匹配或锚例逻辑导致金标准错判的提交会被直接拦下；在线模式下，用它测 LLM 评委与人工标注的符合率，目标不低于 95%。

### 5.3.2 诱饵负样本：188/188 全拒收

把故意做错的答案机械地喂给判卷器：判成"记对了"就是假阳性。诱饵全部确定性生成、可复现，共四类：张冠李戴（拿别的题的期望答案来答本题）、瞎编（期望值改一个字符）、含糊其辞（用自信口吻包装错误答案）、超串近形（给期望值添后缀，专打"子串匹配就给分"的假阳性面）。当前全量 188 条诱饵拒收 188 条（188/188，100%），高于 95% 的门禁线。诱饵与金标准一样离线可跑：判卷逻辑一变即可重测，不需要任何智能体参与。

### 5.3.3 人工盲评：72 条双人分层抽样（流程外校准）

机器自检之外还要和人类对表。`memhall calibrate` 从历史归档导出盲评工作表：抽样框是 18 轮历史运行中通过 verify 核验的 14 轮里、LLM 评委判定的全部 472 条语义判定，按六个能力维分层各抽 12 条、固定种子 20261014，共 72 条，覆盖 35 个题族（机器判 correct 52 条、各类错误 17 条、待复核 3 条）。工作表隐藏智能体、模型与机器判定，题目身份映射单独封存；两名评审独立把每条回答判成六态之一，再算混淆矩阵、一致率与 Cohen κ，分歧条目走终裁。

截至本报告撰写，盲评处于 awaiting_human_labels 状态：真人标签尚未填齐，材料中不存在、也不允许出现任何"一致率"数字——我们不预支校准结论，标签到齐后按协议出正式口径。已知边界同样如实标注：over_persist 在抽样框内只有 6 条候选（该态主要由规则断言判定，不属本次校准对象），按抽样规则 0 条入样；四家被测智能体中仅三家有历史归档（36/18/18 条）。工作表样例如图~blind-review~所示。

> 边界声明：盲评校准的对象是 LLM 评委，不是整套评分系统——规则断言这部分确定性判定不进抽样框，其质量由 5.3.1 的金标准门禁覆盖。两件合起来，才是对全体系的校准。

## 5.4 可解释输出：每个判定都能下钻

只出"对/错"二值分数的系统没法排障：同样是 60 分，可能是没记住，也可能是满嘴跑火车。麟阁的每个探测点判定都落在六态之一（如表~t5-1-verdicts~所示），并附判定依据与证据引用。

【表:t5-1-verdicts|六态判定与典型表现】
| 判定态 | 含义 | 典型表现 |
|---|---|---|
| correct（正确） | 记对了 | 回答或行为与期望一致 |
| omission（遗漏） | 忘了 | 答不出、没按记忆办事 |
| confusion（混淆） | 记混了 | 新旧/相似信息并列使用或交叉作答 |
| fabrication（编造） | 记错了（瞎编） | 无中生有，报出不存在的内容 |
| over_persist（错误持久化） | 不该记的记下了 | 明示"别记"的内容出现在记忆库或被复述 |
| wrong_reuse（错误复用） | 用错了 | 拿过时或张冠李戴的历史信息办事 |

可解释性靠三个机制。其一，判定依据词表化：出题人在题目里写明 verdict_map——"报出新路径判 correct、报出旧路径判 confusion"，LLM 评委只做"把回答归进哪个类别"的分类，引擎把类别映射回六态判定值；判定不是评委的自由发挥，是受词表约束的归位。其二，逐判定给人话解释与证据引用 ID：报告里能从"某智能体边界识别偏低"下钻到那条明示"别记"的口令被复述的原始对话。其三，脚本判定带命中层展开，如"锚例尾段命中（~/dev/src）""锚例命中（重叠率 12/15）"，复核时一眼可见判的是哪层。

判卷器是否真能逮住已知缺陷？mock 适配器提供了"答案已知"的检验面：它是缺陷注入基线，输出为设计模式——该对的对着、该错的错着、该忘不忘都有脚本安排，不是能力地板。判卷在 mock 上画出的画像与注入缺陷一一对应：full 套题包（45 题）总体 66.1%（62/66 计分探测有效）、chains 22.2%（历史口径 v1 分别为 62.2%/41.7%，差异来自口径变更而非行为变更）。mock 六维画像与逐缺陷对应关系见第七章。

## 5.5 无效运行隔离与故障定位

榜单最常见的脏分，是把基础设施故障算成能力缺陷：智能体超时算它"忘了"，记忆导出失败算"空库"，判卷器挂掉算"答错"。不把这些脏分清出去，区分度就是假的。

麟阁的纪律是"证据不足不等于答错，宁弃权不冤枉"，四道闸清出脏分。①运行无效出分母：被测智能体超时、崩溃、后端不可用（AgentUnavailable）时，相关探测点判 invalid_run，单列统计、不进能力分；②证据缺失不折算：记忆导出失败绝不当作空库，证据覆盖不足的断言一律不判；③降级不计分：判卷故障窗口的兜底判定保留值供复核，但剔除出分子分母；④残缺轮进不了归档：部分用例失败的轮次 verify 必挂（退出码 4），混不进任何统计——5.3 盲评抽样框排除 4 轮残缺归档，就是这道闸的实际运作。

这套隔离让六态判定真正对上了赛题"区分正确记忆、遗漏、混淆、错误持久化和错误复用"的评分要求——表~t5-1-verdicts~的六个判定态逐条落位，另加"编造"（fabrication）一类：无中生有和记混是两种不同的失败，混在一起会掩盖病因。

在"判错了"之上，报告层再做行为×存储的交叉定位，把错误再拆一层——故障定位四态：没存（写入故障）、存了没用上（调用故障）、存了但内容错（写入质量/检索串台）、该删没删（边界失效），定位优先级固定；只有行为、没有存储证据的题目不硬定位，单列披露。定位靠记忆快照与对话、行动证据交叉推导。

还有一个容易忽视的分母细节：并非所有探测点都为分数服务。探测点带角色标记——score 进六维分数，diagnostic 只进故障定位与质检层；存储态断言（存没存、存了几个）和操作断言（在行动证据面成熟前）一律 diagnostic。分数的分母因此始终是"证据充分、判卷有效"的语义探测点，诊断信息照常产出但不掺进分数。

最后，以上整条链路由一条命令收尾：`memhall run` 单轮评测、`memhall batch` 多轮固定试卷，manifest、证据、判定、指标、雷达、报告一次产出，`memhall verify` 离线对账封印，如图~cli-run~所示。工具化封装（Web UI、deb/exe）见第六章。
