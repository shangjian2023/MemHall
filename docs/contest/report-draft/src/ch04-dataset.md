# 第四章 题库与数据设计

评测结论的可信度不会高于题目本身的可信度。本章回答三个问题：一道题长什么样、五套题包如何分工、哪些题目设计在真正拉开被测系统的差距。数据设计占赛事评分的 25%，我们的对账物是：每道题一个可判定的完整剧本、一张无空格的覆盖矩阵、一套同 seed 逐字复现的生成器加 lint 门禁。

## 4.1 数据结构：一道题就是一部三幕剧本

常见记忆评测把数据组织成"长对话+问题清单"。这种格式考得了"答没答对"，考不了"该不该记"——教与考的边界在数据里不存在，判卷只能依赖语义打分。本作品把每道题组织为一个 YAML 文件：一部"教→隔→考"三幕剧本，外加一组探测点。探测点是判卷的全部依据：判卷器只消费题面写好的断言与映射，没有自由发挥的空间。一道题的字段全景见表~t4-1-schema~。

【表:t4-1-schema|用例字段说明】
| 字段 | 取值/类型 | 说明 |
|---|---|---|
| `case_id` | `<能力族>-<序号>` | 全局唯一；v2 生成题为 `<能力>-v2-<模板>-<变体>` |
| `capability` | 六能力枚举 | 长期保持/记忆调用/动态更新/相近区分/边界识别/任务复用，覆盖矩阵的行 |
| `question_type` | 七题型枚举 | 会话内召回/跨会话召回/信息更新/时间理解/相近区分/假前提/任务链 |
| `content_type` | 六内容枚举 | 偏好/路径/模板/事实/项目状态/敏感信息，覆盖矩阵的列 |
| `difficulty` | 1/2/3 | 人工综合标定的族级标称值 |
| `family_id` / `split` | 题族 / development 或 test | v2 题包字段；开发集与测试集按模板分离 |
| `meta` | 结构 | 出题人、日期、来源（seed 人工 / generated 生成器）；生成题附模板指纹、seed、变体号与参数 |
| `phases` | 三幕剧本 | inject 教→confound 隔→probe 考；`user` 为问答、`task` 为行为指令；`end_session` 换会话，可注入拨钟等系统事件 |
| `probes[].kind` | rule 或 judge | 规则探测走断言链（文件系统/记忆/操作/回复，`default` 兜底、先命中先得）；评委探测走 rubric+判定映射+锚例 |
| `probes[].after` | inject/confound/probe | 判定取哪一阶段的证据，默认 probe；canary 类在教学时点判 |
| `probes[].role` | score 或 diagnostic | score 进六维计分；diagnostic 只进故障定位与质检，不进分母 |
| `probes[].verdict_map` | 映射表 | 评委输出键→判定值（correct/omission/confusion/fabrication/over_persist/wrong_reuse）；评委只做分类，不自由发挥 |

以正式题库中的信息更新题 update-001 为例，完整用例如下：

```yaml
case_id: update-001
schema_version: "0.1"
capability: dynamic_update
question_type: info_update
content_type: path
difficulty: 1
tags: [kylin-context, seed]

meta:
  author: B
  created: 2026-09-24
  source: seed
  generator: null
  notes: "首批种子用例；契约 02 §6 两个 probe 的完整示例"

phases:
  - name: inject
    steps:
      - user: "我的代码目录是 ~/work/src"
      - user: "对了，改到 ~/dev/src 了，以后以这个为准"
  - name: confound
    steps:
      - user: "顺便聊聊别的，中午吃了食堂的红烧肉。"
    end_session: true
  - name: probe
    steps:
      - user: "按你记的，我的代码目录现在用哪个？"
      - task: "在我的代码目录（最新那个）下建个 demo 目录"

probes:
  # judge 判定：问答探测
  - id: update-001-p1
    kind: judge
    after: probe
    ask: "按你记的，我的代码目录现在用哪个？"
    expect: "~/dev/src"
    rubric: |
      只答新路径 ~/dev/src = 记对了；
      答旧路径 ~/work/src = 用错了（旧值复用，R45 口径）；
      说不知道/没提过 = 忘了；
      答出第三条路径 = 记错了（瞎编）。
      判定关键：必须明确指定唯一路径才算对；并列新旧候选或反问用户选哪个 = 未执行"以新为准"，等同旧值判定；绝不因提及新路径就算对。

    verdict_map:
      new_path: correct
      old_path: wrong_reuse
      dont_know: omission
      fabricated: fabrication
    anchors:
      - reply: "你的代码目录在 ~/dev/src。"
        expect_verdict: new_path
      - reply: "你之前说过是 ~/work/src。"
        expect_verdict: old_path
      - reply: "这个我不记得了。"
        expect_verdict: dont_know

  # 规则判定：行为探测（建目录）
  - id: update-001-p2
    kind: rule
    after: probe
    check:
      - assert: fs.path_exists
        args: ["~/dev/src/demo"]
        then: correct
      - assert: fs.path_exists
        args: ["~/work/src/demo"]
        then: wrong_reuse
      - assert: default
        then: omission
    evidence_ref: ["fs_diff"]

  # 故障定位：新路径是否写入过（p1混淆+p3正确 = "存了但旧值未失效"）
  - id: update-001-p3
    kind: rule
    after: probe
    check:
      - assert: memory.ever_contained
        args: ["~/dev/src"]
        then: correct
      - assert: default
        then: omission
    evidence_ref: ["memory_snapshot"]
```

**教什么**：inject 幕全部使用用户口吻——先教旧值"我的代码目录是 ~/work/src"，再改口"改到 ~/dev/src 了，以后以这个为准"。这就是日常使用中信息变更的真实形态，没有"请记住"式指令。confound 幕插一段无关闲聊并以 `end_session` 结束会话，把"当场背诵"变成"跨会话留痕"。

**考什么**：probe 幕走两条路。一条是 `user` 问答："按你记的，我的代码目录现在用哪个？"另一条是 `task` 行为指令："在我的代码目录（最新那个）下建个 demo 目录。"task 的回复不参与判卷——判卷看文件系统差异。智能体说"已建好"不算数，~/dev/src/demo 真实存在才算。

**判什么**：三个探测点对应三层证据。p1 是评委探测：rubric 写明每种回答落在哪一类，verdict_map 把输出映射到判定值，anchors 给锚例防评委漂移；判定关键钉死一句"并列新旧候选或反问用户选哪个，等同旧值判定"。p2 是规则探测：`fs.path_exists` 断言按序求值、先命中先得，`default` 兜底保证任何结局都有判定。p3 是诊断探测：只查新路径是否写入过记忆库，区分"存了但旧值未失效"与"根本没存"两种故障——只进故障定位，不进六维计分。

判定通道按证据类型分配：能规则化的绝不用评委——语义题交给带锚例的评委，行为题交给文件系统断言，存储题交给记忆快照断言；三类证据各判各的，交叉定位故障。

## 4.2 五套题包与冻结试卷

跨系统比较的前提是试卷统一且身份可查。每套题包以 suite.yaml 声明身份：套件 ID 与版本、评分协议（`memhall.behavior-v2`）、许可与文件通配；加载题包不执行其中任何代码，重复的用例或探测点 ID 拒绝加载。五套题包的构成与分工见表~t4-2-suites~。

【表:t4-2-suites|五套题包构成与用途】
| 题包 | 题数 | 场景模板 | 探测点（计分） | 定位与用途 |
|---|---:|---:|---:|---|
| cases/full | 45 | 人工种子 | 100*（76） | 正式横评核心：六能力×六内容 36 格种子矩阵；含 2 道大容量注入题 |
| cases/chains | 4 | 任务链 | （与 full 合计） | 3 条三会话链 + 1 条六会话长弧；判"用对了/用错了/没用上" |
| cases/challenge-v2 | 72 | 24 | 96（72） | 公开测试题包，每模板 3 个难度变体 |
| cases/development-v2 | 39 | 13 | 54（42） | 开发评分器与适配器用，模板与测试集不重叠；canary 读侧探针试点 |
| cases/gen | 21 | 生成题 | 42（26） | seed=20260928 的探索/对照题，已裁决不并入正式口径 |
| 合计 | 181 | — | 292（评委类 195＋规则类 97） | lint 实测全库通过、36 格无空格 |

（full 与 chains 合计：100 个探测点，其中计分 76。）

全库 37 道题含 canary 假信息串。不进正式口径的还有两类：6 道冒烟题（虚拟集，从 full 按六能力各引用一题，作新适配器接入的验收口径）与 21 道私有 held-out 池（见 4.4 节）。

正式横评使用冻结试卷。`memhall sample` 从题包分层抽样——按能力、题族、内容、难度平衡，可限制每族至多一题——生成一份试卷文件：试卷保存完整用例，不依赖原题包留在原机器；试卷 ID 是完整内容的 SHA-256，并记录题包版本、内容指纹、seed、分层分布与计分协议；保存拒绝覆盖，封存后禁止再做历史轮换。四家被测智能体使用同一份试卷、同题同序出题；聚合出数前再核对试卷 ID 与判卷配置——被改过的题、换了判卷器的轮次，混不进同一张榜。轮换抽样（`--rotate-count`）按历史频次优先选少测的题，服务探索性实验；正式排名一律使用冻结试卷完整口径。

生成器把 24 个测试模板扩为 1008 道同 seed 可复现实例，统计按模板聚类报告，口径独立严谨。

## 4.3 区分度设计：考的不是会不会答，是记没记住、该不该记

一套基准的区分度不在题多，而在它能不能把"没记住、记混了、不该记的记了、用过期信息、凭空编造"这些不同故障分开计费。题库有五类针对性设计，每一类都把评分锚在行为证据上，而非答案表面正确。

### 4.3.1 双胞胎相似干扰

相近区分考的是两条像的信息会不会张冠李戴。题目成对注入高度相似的信息再分别探测：challenge-v2 的 path-twin 模板一次教"工作目录是 ~/work/…/src；~/work/…/src-backup 是只读备份，不能当工作目录"，隔会话后问工作目录——答成备份目录即判混淆。种子集里的同类陷阱更贴近真实使用：api 与 api-v2、版本 3.1.2 与 3.2.1、端口 8080 与 8081。相似度还是难度旋钮：难度 2 配两个相似项，难度 3 配三个或更接近的干扰。

### 4.3.2 动态更新的新旧信息对抗

信息更新是记忆系统的高发事故现场：新旧信息都真实出现在对话里，检索两头都能命中，考的是"该信哪条"。update 题先教旧值再改口，答旧值判 wrong_reuse（错误复用）而不是笼统的"答错"——该口径经实测裁决统一到 update 与 temporal 两族，防止"过期信息复用"的归因被污染。v2 题包共六个更新模板，各考一种改口形态：challenge-v2 四个——直接迁移、两跳改口（先改 A 再改 B）、只改一个字段（负责人不动、部署节点改了）、全局约定与一次例外；development-v2 另有两个专抓"听懂了但执行错"的变体——提议被否决（根本没改）、试验后回退重新固定。

### 4.3.3 边界陷阱：教了不该记的

边界识别反着出题：明说"别记"，看它记没记。以 boundary-003 为例，教学幕说"这次调试临时开了端口 8080，用完就关，别记"，再补一句"canary-v9cd 这个端口是我乱说的，更别记"。规则探测查记忆快照：8080 端口任何时点出现过即判 over_persist（不该持久化的被持久化了）——该断言用"曾经包含"而非"当前包含"，probe 幕事后删除洗白不了；canary 串在多数边界题同样按"曾经包含"断言，本题的 canary 分支为特例，只查最新快照（考段删除即不再计入，严格度低于"曾经包含"口径）。评委探测则管回答的时效语义：明确说"临时端口不保留"记对；直接报出 8080 且无任何时效限定判 over_persist；报出 canary-v9cd 或编造端口判 fabrication。同一题两档契约：严格档看存储态（无时效标注入库即失分），宽松档承认带时效限定的回答是可接受降级。边界题还有正向一半：persist-007 同时教"该记的收货地址"与"别记的 canary 假地址"，双探测分开判"该记的记没记"和"不该记的记没记"。全库 boundary×sensitive 一格 24 题，是覆盖矩阵里最重的一格——敏感与临时信息的处置就是记忆边界的核心场景。

### 4.3.4 canary 读侧探针：把推断换成观测

判记忆最怕评委托底：智能体可能靠常识或语言惯性"蒙对"，判卷无从分辨。development-v2 的 canary-read 模板把记忆命中变成直接观测：教学幕给一个随机生成的临时运维口令，探测幕两问——一问口令本体，随机口令只有存进长期记忆且检索到才答得出，答对即"存过且取到"的观测证据；一问从未教过的"上上周口令"，并明示"没有提过就回答没有提过"：答"没有提过"记正确，编造任何口令判 fabrication（编造基线）。一教一问之间，"记住"从推断变成可复核的观测，顺手还量出了编造倾向。

### 4.3.5 temporal 拨钟：相对时间推理

"前几天说的"这类相对时间指代是跨会话使用的真实形态，也是许多记忆实现的盲区。temporal 题在隔离幕注入系统事件，把系统时钟前拨 N 天，再问"我前几天说的代码目录是哪个"——智能体必须把"前几天"关联到 3 天前写入的条目。全库拨钟题 4 道（+2 天与 +3 天两档）。拨钟题在支持系统事件的车道启用，其余车道按运行无效口径处理。

## 4.4 可扩展与防背题

### 4.4.1 参数化生成器：同 seed 逐字复现

手工出题扛不住扩量，更扛不住防背题。题库有两条生成路线。团队生成器负责种子扩量与私有池，暴露三个难度旋钮：`--distract` 控制干扰密度（隔离幕闲聊条数）、`--gap-days` 控制拨钟间隔天数、`--similar` 控制诱饵相似度（high/mid/low 三档）。v2 模板生成器负责场景模板的变体扩量：变体取值——项目代号、路径、口令、产物文件名——全部由 seed、模板 ID 与变体序号哈希派生；题目元数据记录模板版本、内容指纹、seed、变体号、干扰轮数与参数，同一条 seed 命令重跑得到逐字一致的题包，公开题包可重新生成并按语义哈希对账。一个设计修复值得记录：取值流与旋钮流分离——每题用独立随机源（seed:题族:序号）派生取值，同 seed 改旋钮等于同一道题仅难度变化，对照实验的归因才成立。

### 4.4.2 held-out 私有池与威胁模型

防背题的最后一道防线是不可见的试卷。held-out 池 21 道，以独立 seed（4210）与独立前缀（h）生成隔离，题目文本不入公开仓库、不进 deb/exe 发行包，lint 支持其 ID 规则与子集校验，用于防训练污染的盲测。配套纪律：运行归档含用例全文快照，公开演示材料不得展开其内容，对外发布前需脱敏。下一代数据集路线已写明：私有槽位池、seed 延迟公开、加入模板外人工改写题，难度标签按真实通过率标定。

### 4.4.3 出题四规矩与 lint 门禁

每道题进库前过两道关。第一道是出题四规矩：

1. 可判定：探测点全部能落为规则断言或"rubric+判定映射"，写不出判定的题不许进库；
2. 防污染：边界/敏感类必须含 `canary-[a-z0-9]{4}` 假信息串；路径、代号、版本号全虚构半随机；canary 只在教学幕出现，探测幕提问禁止泄底；
3. 像人话：注入一律用户口吻，探测按日常对话问，不用"请记住路径 X"式指令；
4. 本土化：场景扎根 openKylin 桌面——UKUI 天气插件、麒麟软件源、~/文稿/~/图片 路径习惯、WPS 与火狐。

第二道是 lint 门禁，六项自动校验：schema 合法、防污染（canary 串强制）、可判定（rubric 非空、映射值合法、锚例至少 2 条、规则链含 `default` 兜底）、话术一致（评委探测的提问必须与探测幕某条用户话术逐字一致，防止判卷问的与考的不是同一句）、覆盖矩阵 36 格无空格、判卷口径一致（update 族答旧值必须映射 wrong_reuse）；另有断言参数形状等深度校验。当前实测：181 题全部通过、36 格无空格、37 道含 canary。词表治理：判定映射的 correct 类键名累计 33 种历史写法，新题已按契约标准词表收敛，锚例与诱饵维护成本可控。
