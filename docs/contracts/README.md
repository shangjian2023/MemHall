## 版本与变更纪律（对齐 team-plan.md §4.3）

1. **冻结时点**：三个 schema 于 **09.25（周五集成日）合并冻结为 v0.1**，此后进入变更流程；
2. **变更流程**：改动 = 开 issue（标题 `contract: <编号> <一句话>`）+ @所有消费方 owner + 附迁移说明，全部消费方点头才可合并；跳过流程合并的 schema 改动，reviewer 有权直接打回；
3. **版本号**：本目录文件头部标 `v<主>.<次>`——不兼容改动升主版本并附迁移脚本说明，加字段（向后兼容）升次版本；
4. **实现滞后不算违约**：契约先行的意义是并行开发有依据，M1（09.27）前实现允许缺字段（标 `TODO(contract)`），但字段名、类型、语义不得偏离本文件。

## 三份契约共同的设计约定

- **序列化**：用例与配置用 YAML（人写人读），证据与判定用 JSONL（机器追加写）——边界明确，不混用；
- **时间**：一律 UTC ISO-8601 带时区（`2026-09-27T12:00:00+08:00`）；评测中"模拟隔天"改的是系统时钟，时间戳记录真实 UTC 时间 + 案例时钟偏移量两个值；
- **ID 规则**：`<类型>-<能力族缩写><序号>`，全小写，全局唯一，见各契约的 `id` 字段说明；
- **语言**：用例文本（注入话术、探测问题）默认中文；字段名、枚举值全英文——LLM judge prompt 不受影响，报告双语呈现；
- **禁止项**：任何契约字段不得包含密钥、真实个人信息、VM 密码；测试用真人设定一律用虚构人设（生成器参数化生成）。
