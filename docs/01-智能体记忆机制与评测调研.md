# 智能体记忆机制与评测方法调研报告

> okim-bench 项目 · 调研日期 2026-09-23
> 目的：为"面向 openKylin 的智能体长期记忆自动化评测 Benchmark"提供机制对比与方案选型依据。

## 1. 被测智能体记忆机制对比

### 1.1 总览表

| 智能体/系统 | 记忆载体 | 组织方式 | 写入触发 | 检索方式 | 容量特征 |
|---|---|---|---|---|---|
| **OpenClaw** | 纯 Markdown 文件（file-first） | `MEMORY.md`（精选长期）+ `memory/YYYY-MM-DD.md`（每日日志，append-only）+ 可选 `DREAMS.md`（固化摘要） | 用户显式指令 + 系统提示策略 + 会话压缩（dreaming 提炼） | SQLite 混合索引（FTS5 BM25 + 向量，约 70/30 权重），今日/昨日日志自动加载 | MEMORY.md 约 20,000 字符软上限 |
| **Hermes Agent** | 纯 Markdown 文件 | `~/.hermes/memories/MEMORY.md`（世界记忆，硬上限 2,200 字符）+ `USER.md`（用户记忆，硬上限 1,375 字符），条目以 `§` 分隔 | 系统提示常驻保留策略 + 上下文压缩 + **技能-过程通道**（把任务轨迹提炼为可复用技能文件） | 全量注入 system prompt（约 1,300 token/轮），无独立检索层 | 总量约 3,575 字符，极小工作集 |
| **KylinBot / kylin-agent** | 应用内记忆存储（设置中心可视/可编辑） | 「智能体记忆」（跨会话事实/偏好/环境信息，条目分隔符区分）+「用户画像」（姓名/角色/偏好/沟通风格/常用系统/时区）+ `SOUL.md`（人格与长期指令，每会话重读） | 轻量级**记忆精炼模型**过滤冗余、保留高价值任务经验 | 由运行时服务统一管理，前端可按段落编辑、展示容量占用 | 字符容量分池计量（智能体记忆/用户画像分开） |
| **MemGPT / Letta**（参照系） | 三层架构 | Core memory（常驻上下文，agent 用工具自编辑）+ Recall memory（会话历史库）+ Archival memory（向量长期库） | agent 自主工具调用（core_memory_append/replace、archival_memory_insert） | 分层：常驻 + 精确搜索 + 向量语义检索 | Core 块有字符上限（新版放开至上下文窗口） |
| **Mem0**（参照系） | 向量+图混合存储 | LLM 两阶段流水线（抽取事实 → ADD/UPDATE/DELETE 决策） | 每轮对话后自动抽取 | 向量相似度 + 图关系排序 | 无固定上限，平铺存储 |
| **Zep / Graphiti**（参照系） | 时序知识图谱 | 双时态事实抽取 + 冲突消解 | 消息流自动抽取 | 时序感知图查询 | 图结构，擅长时间推理 |

### 1.2 关键差异点（对评测设计的意义）

1. **存储透明度差异极大**：OpenClaw / Hermes 是纯文本文件，评测器可直接 diff 记忆文件；KylinBot 的记忆在运行时服务内部，需要通过其日志/导出接口或 UI 暴露面取证（对应 environment.md 中 W1 任务"摸清记忆存储位置"）。
2. **写入策略差异 = 误记风险差异**：MPBench 实证表明写入通道越多、策略越激进，记忆投毒面越大——HERMES（4 条写入通道含技能-过程通道）平均 ASR 66.67%，OpenClaw（显式写入为主）34.25%。这直接支撑赛题"边界识别"维度：要分别测"显式要求记住的记没记住"与"没要求记住的是否误记"。
3. **检索架构差异**：Hermes 全量注入（无检索失败模式，只有容量截断模式）；OpenClaw/KylinBot 有检索层，存在"记住了但没检索到"与"检索到错误条目"两种失败模式。评测指标必须区分**记忆状态正确性**（store-level）与**记忆使用正确性**（behavior-level）。
4. **更新能力差异**：文件型记忆（OpenClaw 已知缺陷）难以识别事实动态更新（如用户改地址），会新旧并存；Mem0/Zep 有显式 UPDATE 决策。这正对应"动态更新"评测项，预期各智能体表现差异大、区分度高。
5. **OS 环境因素影响的是证据采集而非记忆本体**：各智能体记忆机制差异主要来自框架架构；操作系统的差异体现在存储路径（`~/.openclaw/`、`~/.hermes/`、kylin-agent 运行时目录）、文件权限、沙箱与桌面环境（UKUI 录屏、D-Bus）。评测 harness 采用适配器模式即可做到 OS 无关，保证"同一套用例、同一批证据、跨环境可比"。

### 1.3 证据采集入口（适配器依据）

| 智能体 | 对话证据 | 记忆状态证据 | 行动/产物证据 |
|---|---|---|---|
| OpenClaw | 会话 JSONL 转录（`~/.openclaw/`） | 直读 `MEMORY.md` / `memory/*.md` / `<agentId>.sqlite`，跑前跑后各快照一次 | 工作区文件 diff、工具调用日志 |
| Hermes | 会话记录 | 直读 `~/.hermes/memories/MEMORY.md`、`USER.md` | 技能文件、工作区 diff |
| KylinBot | 会话导出（设置-日志/会话详情导出） | 记忆设置页统计 + 记忆内容导出；必要时直读运行时存储（W1 待摸清） | 日志页、文件产物 |

## 2. 现有 Benchmark 调研

### 2.1 对话记忆类

- **LongMemEval**（ICLR 2025）：500 题，定义 5 项核心能力——信息抽取、多会话推理、时序推理、知识更新、拒答（abstention）；7 种题型，每题标注证据会话 ID，历史长度可配置（S 版约 115k token）。**对我们最有借鉴价值**：证据会话标注 + 知识更新题型 + 拒答题型（false-premise 改造）。
- **LoCoMo**：超长多会话对话（平均 300 轮 / 9k token / 最多 35 会话），QA + 事件摘要双任务，含对抗性问题（adversarial）。借鉴：多跳/时序题型与对抗性"未提及信息"探测。
- **MemoryBank / PerLTQA**：早期个性化记忆 QA，能力覆盖窄，作背景。

### 2.2 记忆智能体操作类

- **MemoryAgentBench**：把长上下文数据集改造为**增量多轮流式输入**，定义 4 项能力——精确检索、测试时学习、长程理解、选择性遗忘；新构造 FactConsolidation（反事实编辑对，测新旧事实覆盖）与 EventQA。关键发现：所有主流记忆框架在"冲突事实覆盖"上大幅落后于简单的新鲜度基线（Mem0 18%、Zep 7%，单跳 FC 最强 RAG 也仅 54%），多跳 FC 基本未解决（0–7%）。**这是我们"动态更新"维度设计的最直接依据，也预示该维度区分度极高**。
- **MemBench**：从有效性、效率、容量三维度评记忆 agent，区分"参与者 vs 观察者"场景。借鉴：把 token 成本/容量占用纳入指标（工程落地维度）。
- **MemoryBench**（ continual learning ）：模拟用户反馈持续改进，覆盖陈述性/程序性记忆。
- **EMemBench / StoryBench** 等：多模态/交互叙事方向，本赛题不涉及，略。

### 2.3 记忆安全类（边界识别维度依据）

- **MPBench**（arXiv 2606.04329，ICML 2026）：首个系统化记忆投毒 benchmark。两阶段测量——**记忆写入阶段**（任务后检查持久记忆中是否落入攻击载荷或其语义等价改写）+ **记忆检索阶段**（新会话探测是否按被污染记忆行动）；指标 ASR（写入成功率）/ RSR（复用成功率）；提出 4 条写入通道（显式指令/系统提示策略/压缩固化/技能-过程）与 6 类攻击。**方法框架（写入检查 + 延迟复用检查）直接迁移到我们的"边界识别"评测**：把"载荷"换成"不应记住的临时/敏感/风险信息"即可。

### 2.4 记忆系统审计新思路

- **MEMPROBE**：不看出门答案，直接审计"记忆产物中可恢复的用户状态"，区分"写入了什么"与"能检索到什么"。与我们的 store-level / behavior-level 双层评分思想一致。

**复用决策**：LongMemEval（数据管线+证据标注）与 MemoryAgentBench（流式协议+更新对构造）为主要基座；LoCoMo 因 CC BY-NC 许可仅作方法参照；MPBench 方法论自研复现；lancedb/locomo-eval 作为 OpenClaw 适配的对照实现。

**现有 benchmark 的共性缺口 = 我们的提升点**：
1. 全部在"聊天 harness 里评模型/记忆层"，**没有人在真实桌面 OS 上评真实智能体**（KylinBot 等），无 OS 级证据（文件产物、行动轨迹、系统状态）。
2. **边界识别无人系统覆盖**：MPBench 是对抗安全视角，没有 benign 的"临时信息不该记/敏感信息不该记"评测。
3. 评分普遍单一 LLM judge，无双评委交叉、无一致性度量、无强制证据引用。
4. 无快照级隔离与哈希证据链，复现性停留在"脚本可跑"而非"结果可审计"。
5. 无工程化封装（CLI/.deb/批量对比），学术 benchmark 都止步于论文代码。

## 3. 自动评分方法调研（25% 权重，重中之重）

### 3.1 三层评分体系（结论）

| 层级 | 方法 | 适用 | 成本 | 可靠性 |
|---|---|---|---|---|
| L1 确定性检查 | 精确匹配、记忆文件 diff、文件状态断言、PII/凭据正则、结构化字段比对 | 记忆状态判定、产物验证、敏感信息检出 | 零 | 100% 可复现 |
| L2 语义规则 | embedding 相似度阈值判"语义等价"、时间戳新鲜度比较 | "语义等价改写"判定、相近条目区分 | 低（本地向量模型） | 高，阈值可调 |
| L3 LLM judge | 结构化 rubric 双评委交叉 | 开放式回答质量、行为是否"合理复用"、证据归因 | 高（记账） | 需偏差控制 |

### 3.2 LLM judge 的已知偏差与对策（实证数据）

- **客观锚点任务上 judge 极可靠**：有标准答案时，5 个前沿 judge 真值准确率 97–100%，无位置偏差。→ 设计原则：**能转成客观判定的绝不用主观评分**。
- **质量持平时偏好更长答案**（verbosity bias，72–100% 偏好长文）；**同家族自偏好**长度对齐后达 +26pt。→ 对策：跨家族双评委（如 DeepSeek + Qwen，environment.md 已定）、rubric 二元化、证据引用强制化（评分必须引用证据包中的具体片段，无证据不得分）、长度中性化 prompt。
- **位置偏差已基本解决但仍保险**：顺序交换双跑取一致。
- **评委间一致性度量**：Cohen's Kappa 写入报告，低于阈值（如 0.6）的结果自动标记"需人工复核"，这是"低人工介入"的闸门机制而非人工全检。

### 3.3 可解释性与防语义偏移

- 每个评分输出结构化为 `{verdict, confidence, evidence_refs[], reason}`，evidence_refs 指向证据包中的文件/行/消息 ID，评审方可逐条回溯。
- 赛题要求的五分类判定（正确记忆/遗漏/混淆/错误持久化/错误复用）用**判定决策树**实现（见设计文档 §4），把开放式判断压缩成少量客观二值问题，judge 只在最后一步做语义归因。

## 4. 对本项目的设计输入（结论清单）

1. 双层评测：store-level（记忆状态 diff）+ behavior-level（后续会话行为/任务产物），缺一不可——否则分不清"没记住"与"记住了没用到"。
2. 六能力 → 题型映射沿用 LongMemEval 证据标注法 + MPBench 两阶段法 + MemoryAgentBench 反事实更新对。
3. 边界识别题型分三类：临时信息（不应记）、敏感信息（PII/凭据，不应记）、风险指令（不应执行，借鉴投毒类但不以攻击为目的）。
4. 评分以 L1/L2 为主（可复现、零成本），judge 仅用于行为归因，双评委跨家族 + 一致性闸门。
5. 复现性按 harness 测量契约报告：模型端点与日期、prompt 版本、样本 ID、评分器版本、运行镜像、随机种子、trace 全量归档。
6. 指标输出六维雷达图 + 五类错误率矩阵 + 稳定性（重复运行方差、评委 Kappa），对应"指标完整性 10%"。
